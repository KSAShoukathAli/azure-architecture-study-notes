2 Service Bus: queue vs topic

Queue = one logical work stream

Multiple workers can compete for messages from one queue. One message is processed by one receiver path.

Topic = one publish, many independent subscriptions

Each subscription is its own durable message stream. Subscription rules and filters decide which messages a subscriber receives.

3 Receive modes define the failure tradeoff

ModeWhat happensArchitect consequence
Peek-LockMessage is locked first and removed only after successful settlement.Protects against loss but redelivery can occur. Design for idempotency.
Receive-and-DeleteBroker removes the message as it delivers it.Lower protocol overhead, but consumer failure after receipt can lose work.
important

At-least-once means duplicates are normal failure behavior. A consumer can finish the business work and fail before completing the Service Bus message. The broker cannot know that the side effect happened.

Lock duration

The default Peek-Lock duration is 1 minute. The entity can be configured up to 5 minutes. For longer processing, renew the lock manually or use SDK auto-renewal.

Prefetch caution

Prefetched messages are already locked while they wait in the local client buffer. If processing is slow or the prefetch count is too large, locks can expire before work begins.

4 Sessions: FIFO for related messages

Use SessionId when messages for the same business key must be processed together and in order. Sessions are supported in Standard and Premium, not Basic.

design question

Do you need global ordering, or ordering only per business key? Global ordering destroys parallelism. Per-key ordering through sessions usually scales better.

5 Dead-letter queue: operational recovery path

Common DLQ causes include delivery count exhaustion, explicit dead-lettering, TTL expiration when dead-letter-on-expiration is enabled, and subscription filter evaluation failures. The default maximum delivery count is 10.

DLQ runbook
  1. Capture DeadLetterReason and description.
  2. Identify code/data/dependency cause.
  3. Fix the cause before resubmission.
  4. Resubmit deliberately; do not create an infinite poison-message loop.
  5. Track DLQ depth with alerts.

6 Duplicate detection does not replace idempotency

Service Bus duplicate detection remembers application-controlled MessageId values for a configured window. Standard and Premium support it; Basic does not. Duplicate detection must be enabled when the queue or topic is created. The window can be changed later.

A duplicate send still reports success to the producer, but the broker silently drops the duplicate. With partitioning enabled, uniqueness uses MessageId plus PartitionKey. This still does not solve receive-side redelivery, so consumer idempotency needs a stable business/message identifier plus durable state.

Choose Premium when dedicated capacity, predictable latency, private networking, larger payload support, or native multi-region messaging is an architecture requirement - not simply because production means premium.

Geo-Disaster Recovery

Premium. Replicates namespace metadata/configuration, not message data.

Geo-Replication

Premium. Replicates both metadata and message data to secondary regions.

Large payloads: use claim-check deliberately

Claim-check pattern: keep the broker message small. Store a large FHIR bundle, attachment, or document in Blob/Data Lake and send only a secure reference plus metadata through Service Bus.

9 Event Grid: announce that something happened

Event Grid is optimized for discrete events. A publisher announces a fact such as PrescriptionSubmitted or BlobCreated; subscribers decide what to do.

Push delivery

Event Grid sends the event to a configured handler. It retries transient failures and can dead-letter when configured.

Namespace pull delivery

Consumers pull events when they need control over receive timing, cannot expose an endpoint, or need a private-link receive path.

Event Grid push delivery is at-least-once and does not guarantee ordering. Consumers should tolerate duplicates and out-of-order events.

Event Grid has two resource models

ModelResourcesDelivery
Event Grid basicSystem topics, custom topics, domains, partner topicsPush subscriptions to handlers
Event Grid namespacesNamespace topics and subscriptionsPush or pull; CloudEvents-oriented model

For webhook push, the endpoint must complete Event Grid endpoint validation. Push delivery retries failures for a bounded period; configure dead-lettering to Blob Storage when undelivered events must be retained for investigation.

10 Event Hubs: a retained partitioned stream

Event Hubs is not a work queue. Reading an event does not remove it. Events remain for the retention period, and each consumer group maintains its own view of progress.

ConceptMeaning
PartitionOrdered lane in the stream. Ordering is guaranteed within the partition.
Partition keyRoutes related events to the same partition when per-key order matters.
Consumer groupIndependent logical reader of the same stream.
OffsetPosition of an event within a partition.
CheckpointSaved progress so a processor can resume.
CaptureAutomatically writes the stream to Blob Storage or Data Lake for a cold/batch path.
do not confuse

Service Bus asks: who owns this unit of work? Event Hubs asks: where is each consumer in the stream?

Capture

Capture persists the stream to Blob Storage or ADLS for a cold/batch path. Native Event Hubs Capture writes Avro; use downstream/no-code processing when Parquet is required.

Checkpoint caution

If one event requires long selective retries, advancing the partition checkpoint becomes awkward. That is a clue you may be modeling queue-style work on a streaming log.

audit boundary

Event Hubs retention is not a long-term audit archive. If compliance requires durable audit retention, capture/export events to storage with the required retention and immutability policy.

11 Security and networking

Prefer Entra ID and managed identity with least-privilege data-plane roles where supported. Treat network reachability separately from authorization. For Service Bus, Private Endpoint/Private Link requires Premium tier; Event Hubs private networking depends on its tier. RBAC still decides whether an identity can send or receive.

For private connectivity, reuse the networking model: Name -> Address -> Route -> Allow.

13 September 2026 SDK retirement

current

September 30, 2026 has two different consequences:

  • SBMP protocol: support ends and workloads that still depend on SBMP must move to AMQP; SBMP is no longer usable after the cutoff.
  • Legacy SDK libraries: WindowsAzure.ServiceBus, Microsoft.Azure.ServiceBus, and com.microsoft.azure.servicebus may continue running over supported transport, but Microsoft support and updates end.
  • Target: move to current Azure SDK libraries such as Azure.Messaging.ServiceBus.
