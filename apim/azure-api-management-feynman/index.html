Azure API Management - Feynman Way of Understanding

problem -> mechanism -> prediction -> failure -> boundary
Goal: do not memorize APIM features. Rebuild them from the problem an API boundary must solve.

1 Start with the problem, not APIM

Imagine many consumer teams calling many backend services. If every consumer knows every backend URL, auth scheme, retry rule, throttling limit, and migration schedule, integration policy is distributed everywhere.

You need one controlled boundary that separates the public API promise from backend implementation details.

WHO?
WHERE?
CHANGE?
PROTECT?
SEE?

2 Derive the gateway

A caller sends a request. Before the backend sees it, someone must decide:

  • Is this caller allowed?
  • Which operation did they ask for?
  • Which backend should receive it?
  • Should the path, headers, or body change?
  • Is the caller sending too much traffic?
  • What happens if the backend is unhealthy?
  • How will we prove what happened later?

Put that machinery in front of the backend and you have an API gateway.

3 Authentication has two independent trust decisions

The first token answers whether APIM trusts the caller. It does not automatically answer what identity the backend should trust.

predict

The caller token has audience api://frontend-api, but the backend accepts only api://orders-backend. Should APIM blindly pass token A through? No. Either the backend contract intentionally accepts it, or APIM must obtain/send a different backend credential.

This is why validate-azure-ad-token and authentication-managed-identity solve different trust hops.

4 A subscription key is not OAuth

OAuth/JWT answers: Who is the security principal and what claims does it hold?

An APIM subscription answers: Which APIM consumer is entitled to this API/product and which APIM product context applies?

boundary

You may require both. Removing the subscription requirement does not add OAuth security. Adding a subscription key does not replace JWT authorization.

5 Routing is string composition plus network reachability

When a request becomes a 404 after onboarding, calculate the final URL before blaming Azure:

  1. Gateway hostname
  2. API suffix
  3. Operation path
  4. rewrite-uri
  5. Backend base URL or backend entity
break it

If the backend base ends with /api/ and your rewrite begins with /api/orders, what exact path does APIM send? Predict it before running the test.

6 Networking: ask which direction needs privacy

Do not memorize endpoint vs integration vs injection. Ask direction first.

QuestionFeature
Must private clients reach APIM without public ingress?Inbound Private Endpoint, where the tier supports it.
Must APIM reach a private backend?Standard v2 / Premium v2 VNet Integration, or an injected gateway.
Must the gateway itself live in the VNet boundary for inbound and outbound traffic?Premium v2 VNet Injection or classic Developer/Premium injection.
classic internal-mode trap

If APIM in classic internal VNet mode calls its own gateway hostname as a backend, what path does that request take? Microsoft documents a load-balancer limitation that can produce 500 BackendConnectionFailure. That is a network-path problem, not an API-code problem.

7 Policies are a four-stage machine, with request-time state

Why inbound, backend, outbound, and on-error? Because a proxy request has four natural moments: before the backend, at the backend hop, after the backend, and the failure path.

The context object is the request-time state. Policy expressions read and modify that state. Fragments let you reuse policy blocks without copy-pasting XML.

inheritance trap

A global auth policy works everywhere except one operation. Before debugging Entra ID, inspect the effective policy and ask whether a child scope removed <base />.

8 Rate limit and quota are different capacity contracts

The backend can be perfectly secure and still collapse under legitimate traffic.

Rate limit

How fast may traffic arrive right now? Counters are gateway-local in distributed deployments.

Quota

How much usage is allowed across the quota window? The quota counter is global at the APIM service level.

predict

You deploy the same API in two APIM regions. A client sends traffic to both. Should you assume one globally exact rate-limit counter? No. That is exactly where rate limit and quota diverge architecturally.

9 Backend failure: did APIM call the backend at all?

A 503 or 500 at the client can have different stories. DNS/TLS/policy/circuit-breaker failures can originate in APIM before the backend runs. A backend can also return its own 5xx.

context.LastError, dependency telemetry, backend logs, and correlation IDs tell you which story happened.

breaker question

If the circuit breaker is open, APIM can return 503 without sending the request to that backend. Who owns that 503? The gateway policy/resilience layer, not backend application code.

10 Caching is an optimization, not protection

Built-in cache is convenient. External Redis-compatible cache gives more control and capacity and can support scenarios where built-in cache is unavailable.

predict

If your cache disappears and every request becomes a cache miss, what prevents the backend from being flooded? The answer must still be rate limits, capacity controls, and backend resilience.

11 Version or revision? Ask what promise changed

If consumers must change because the external contract broke, create a new version. If the same client contract should keep working while you alter policy/spec/backend behavior, use a revision to test and promote safely.

12 Classic vs v2: ask what capability you cannot give up

Do not think of v2 as simply newer and therefore better for every case. Ask which architectural capability is non-negotiable.

decision test

You need managed multi-region, self-hosted gateway, and backup/restore. Would you choose Premium v2 because it is newer? No. Current v2 does not provide those capabilities; classic Premium remains relevant.

13 What APIM is not

This boundary matters especially in enterprise integration. APIM governs API traffic. Logic Apps / Integration Accounts handle B2B/EDI workflows such as X12, EDIFACT, and AS2. Specialized transports such as MLLP terminate in an appropriate protocol component.

Architect habit: choose the component from the integration problem. Do not force every integration through the API gateway.

14 Onboarding is proving six contracts

  1. SPEC: does the OpenAPI contract match the intended public surface?
  2. AUTH: how is the caller authenticated/authorized?
  3. PATH: what exact backend URL is produced?
  4. NETWORK: can APIM resolve and reach it?
  5. PROTECT: what rate/quota/cache/retry/breaker behavior is safe?
  6. OBSERVE: can one business transaction be traced end-to-end?

Onboarding is proving six contracts, not clicking "Import API".

15 Debug by moving hop to hop

  1. What HTTP status did the caller get?
  2. Did APIM receive the request?
  3. Did subscription/JWT/certificate policy accept it?
  4. What did policy mutate?
  5. What exact backend URL did APIM call?
  6. Could APIM resolve and connect?
  7. Which credential was sent downstream?
  8. Did the breaker block the request?
  9. Did the backend answer, time out, throttle, or reject?

16 Blank-page explanation

say this without notes

Problem: consumers should not depend on backend security/network/implementation details.
Mechanism: APIM inserts a programmable gateway boundary.
Flow: client -> inbound policy -> routing/auth -> backend -> outbound policy -> client; failures jump to on-error.
Protection: auth plus rate/quota/cache/retry/pool/circuit breaker.
Networking: separate inbound privacy from outbound reachability.
Lifecycle: versions for new promises, revisions for safe change.
Boundary: APIM governs APIs; B2B/EDI and specialized transports belong in other components.
Failure: prove where the request stopped before assigning ownership.

17 Break the model

exercises
  1. Caller gets 401 before backend execution. Which APIM mechanisms can cause it?
  2. Caller gets 403 with a valid JWT. What claim/product/subscription/policy possibilities remain?
  3. You have two regions. Why can rate limit and quota produce different aggregate behavior?
  4. APIM returns 503 and backend logs show no request. Which APIM mechanisms could have manufactured it?
  5. Public backend works, private backend times out. Walk Name -> Address -> Route -> Allow.
  6. Global auth works everywhere except one operation. What does <base /> make you inspect?
  7. Backend base is https://x/api/; rewrite is /api/orders. Predict the final URL.
  8. You need multi-region plus self-hosted gateway. Which tier family remains relevant and why?
  9. You receive X12 over AS2. Why is APIM not the primary engine for that leg?
