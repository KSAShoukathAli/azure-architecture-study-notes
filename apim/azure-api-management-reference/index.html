Azure API Management - Reference Notes

gateway flow - policies - identity - networking - lifecycle - resilience - observability - delivery
The one-line model: APIM is a programmable API boundary. It accepts a client request, applies policy, chooses and authenticates the backend, forwards the call, processes the response, and records telemetry.
Quick map: components · policy pipeline · auth · products · routing · networking · protection · policy code · versions/revisions · cache · observability · onboarding · workspaces · tiers · boundary · troubleshooting

1 What APIM actually contains

ComponentJob
Gateway / data planeReceives API traffic, evaluates policies, forwards requests, processes responses, and emits telemetry.
Management planeConfigures APIs, products, policies, named values, backends, users, subscriptions, gateways, and workspaces through portal, ARM/REST, Bicep, Terraform, or pipelines.
Developer portalConsumer-facing API discovery, documentation, and subscription onboarding where supported.
Self-hosted gatewayContainerized gateway available in classic Developer/Premium, useful when gateway execution must stay near on-premises or multicloud backends. It is not available in v2 tiers.
architect distinction

The management plane configures APIM. The gateway handles runtime API traffic. Keep control-plane reachability problems separate from data-plane request failures.

2 The policy pipeline

SectionTypical work
inboundValidate JWT, check subscription/claims, rewrite URI, set headers, choose backend, rate limit, cache lookup.
backendForward, retry, or otherwise control the backend request stage.
outboundTransform response, remove internal headers, cache store, normalize response.
on-errorInspect context.LastError, log, and return a controlled error contract.
inheritance trap

Policies can exist at broader and narrower scopes. <base /> controls parent-policy inheritance. Removing it can silently bypass global or product guardrails.

3 Caller authentication and backend authentication are different hops

Caller -> APIM

Use validate-azure-ad-token for Microsoft Entra tokens or validate-jwt for generic JWT validation. Check issuer/audience and the claims your authorization model requires.

APIM -> backend

Pass through the caller token only when that is deliberately the backend contract. Otherwise APIM can use Managed Identity, a certificate, a key, or another credential appropriate to the backend.

Hole-finding: Who authenticates the caller? Who authorizes the operation? What credential crosses the APIM-to-backend hop?

4 Products, subscriptions, and subscription keys

A product bundles APIs and can apply product-level policy and onboarding rules. A subscription grants APIM access at a scope and carries primary/secondary keys.

do not confuse these

A subscription key is an APIM access and entitlement mechanism. It is not OAuth2/OIDC authentication. Many designs intentionally require both a subscription and JWT authorization.

5 Frontend contract, backend destination, and backend entities

Importing OpenAPI creates the frontend contract. APIM can expose that public shape while routing to a different backend URL.

MechanismPurpose
rewrite-uriChange the request path before forwarding.
set-backend-serviceSelect a backend URL or named backend entity.
Backend entityCentralize runtime URL, credentials, certificate settings, circuit breaker, and optional pool membership.
Backend poolDistribute or shift traffic across multiple backend entities.
Common 404 trap: API suffix + operation template + rewrite + backend base URL must compose into the path the backend actually serves. Calculate the final URL on paper.

6 APIM networking modes and internal VNet traps

ModeDirectionKey point
Standard v2 / Premium v2 VNet IntegrationOutboundGateway stays publicly reachable unless inbound privacy is configured separately. APIM can reach connected and peered networks when DNS/routing permit.
Inbound Private EndpointInboundPrivate access to the managed gateway. Supported on Developer, Basic, Standard, Standard v2, Premium, and Premium v2; not Consumption or Basic v2.
Premium v2 VNet InjectionInbound + outboundFull VNet isolation for gateway traffic on the v2 platform.
Classic Developer/Premium injectionInbound + outboundExternal or internal mode with explicit subnet, NSG, DNS, and service dependency requirements.
classic injection gotchas
  • The APIM subnet is dedicated to the APIM instance; network location requirements depend on the networking model.
  • NSGs and required Azure dependencies matter. Forced tunneling can break management-plane symmetry unless required service traffic is routed correctly.
  • If you point the VNet at custom DNS, APIM must still resolve all required Azure and backend names correctly.
  • In classic internal VNet mode, a self-chained call to the same gateway hostname can fail with HTTP 500 BackendConnectionFailure. For send-request, Microsoft documents the localhost loopback workaround with the correct Host header.
Reuse the networking model: NAME -> ADDRESS -> ROUTE -> ALLOW.

7 Rate limits, quota, backend pools, and circuit breakers

ControlArchitectural meaning
rate-limit / rate-limit-by-keyProtect against request bursts. Counters are enforced per gateway replica/region/workspace gateway, not as one globally aggregated service counter. Classic uses a sliding-window implementation; v2 uses token bucket behavior.
quota / quota-by-keyEnforce usage across a renewable or lifetime volume/bandwidth window. Quota counters are global at the service instance level.
Backend circuit breakerStops sending traffic to an unhealthy backend. When the breaker blocks a call, APIM returns 503. Currently one circuit-breaker rule can be configured per backend.
Backend poolUp to 30 backends per pool. Load balancing can be round-robin, weighted, or priority-based, with optional session affinity.
v2 counter caution

When the same rate-limit counter key is reused across multiple v2 policy scopes, keep the configured token limits consistent. Use different keys when you want truly separate counters.

8 Policy expressions, the context object, and fragments

Policy expressions are C#-style expressions embedded in policy XML. The built-in context object exposes request-time state such as context.Request, context.Subscription, context.Variables, context.Backend, and context.LastError.

Policy fragments let you package reusable policy blocks and include them in policies. Good fragments have one responsibility and communicate through explicit context variables rather than hidden assumptions.

Interview framing: policy XML is the pipeline; context is the request-time state; fragments are reusable pipeline building blocks.

9 Versions vs revisions

ChooseWhen
VersionThe external API contract changes in a way that requires consumers to opt into a new promise.
RevisionThe same consumer contract should continue while you safely test policy, spec, or backend changes and later make the revision current.

10 Caching: built-in vs external

APIM can use the built-in cache or an external Redis-compatible cache. External cache is useful when you need more control/capacity, want to avoid built-in-cache clears during service updates, or need caching in scenarios where the built-in cache is unavailable.

Design cache keys carefully. vary-by-header and vary-by-query-parameter can prevent serving the wrong representation across users, tenants, languages, or query shapes.

11 Named values and Key Vault

Named values let policies reference configuration without scattering literals across XML. For secrets, use APIM Managed Identity with a Key Vault-backed named value. Versionless secret references are useful when you want APIM to pick up rotations automatically.

12 Observability and tracing

Application Insights can receive request, dependency, exception, and trace telemetry from APIM. Azure Monitor provides metrics and diagnostic integrations. At scale, sampling matters because logging every request can reduce throughput.

trace today

Do not rely on the old subscription-based Ocp-Apim-Trace workflow. Current request tracing uses the supported time-limited debug authorization mechanism / portal test tools.

13 API onboarding and IaC

Prove six contracts:
  1. SPEC - OpenAPI imports cleanly and operation templates are correct.
  2. AUTH - subscription, JWT, certificate, and claims requirements are explicit.
  3. PATH - exact backend URL and rewrite composition are known.
  4. NETWORK - DNS, routing, firewall/NSG, private endpoint path are proven.
  5. PROTECT - rate/quota/cache/retry/circuit-breaker behavior is intentional.
  6. OBSERVE - correlation, diagnostics, ownership, and alerting are defined.

Use revisions as a controlled test surface, then promote. When platform lifecycle and API onboarding have very different cadence/blast radius, separate their Terraform state and pipelines.

APIOps later

14 Workspaces: delegate without giving away the platform

Workspaces let platform teams delegate API/product/subscription ownership using workspace-scoped RBAC while retaining shared governance. Current tier support includes Basic v2, Standard v2, Premium, and Premium v2.

15 Classic vs v2 is an architecture decision

NeedCurrent implication
Multi-region managed APIMClassic Premium supports it; Premium v2 currently does not.
Self-hosted gatewayClassic Developer/Premium; unavailable in v2 tiers.
Backup/restore or static IPAvailable in selected classic tiers; unavailable in v2 tiers.
Fast provisioning + outbound private backend reachabilityStandard v2 is often the natural fit.
Full v2 VNet isolation + availability zonesPremium v2.
Inbound Private EndpointDeveloper, Basic, Standard, Standard v2, Premium, Premium v2. Not Consumption or Basic v2.
v2 is not an upgrade button

Current Microsoft documentation lists several classic capabilities as unavailable in v2, including multi-region, self-hosted gateway, backup/restore, static IP, Event Grid events, Git-based service configuration, direct Management API access, DDoS Protection integration, and resource move. There is no automated migration from an existing classic service to v2.

16 What APIM is not

APIM is an API management gateway, not a general-purpose B2B/EDI engine. Put API contracts and API traffic through APIM; use Logic Apps / Integration Accounts for X12, EDIFACT, AS2, maps, and B2B orchestration. Use an appropriate dedicated component for transports such as MLLP, then expose governed APIs where that boundary makes sense.

17 Troubleshoot in this order

#QuestionEvidence
1Did the request reach APIM?Gateway status, custom domain/DNS/TLS, request telemetry.
2Was the caller accepted?401 vs 403, subscription requirement, issuer/audience/app/scope/role.
3What did policy mutate?Effective policy, context variables, headers, rewrite results.
4What exact backend URL was chosen?API suffix + operation + rewrite + backend base.
5Can APIM resolve and route there?Name -> Address -> Route -> Allow; NSG/firewall/private endpoint/custom DNS.
6Which credential crossed the backend hop?Caller token pass-through vs MI/cert/key.
7Did APIM manufacture the failure?context.LastError, circuit-breaker 503, policy exception, timeout.
8Did the backend answer?Dependency telemetry, backend logs, correlation ID.
