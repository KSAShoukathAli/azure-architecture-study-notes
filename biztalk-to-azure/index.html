BizTalk to Azure Mapping

modernize responsibilities - not boxes
The mental model: BizTalk bundles receiving, normalization, routing, orchestration, transformation, delivery, tracking, and persistence into one product. Azure does not replace that product with one product. Start with Logic Apps Standard, then introduce other services only where a separate architectural boundary is useful.
REFERENCE

BizTalk to Azure - Reference Notes

Architect-level mapping of receive locations, adapters, pipelines, MessageBox routing, orchestrations, correlation, send ports, BRE, B2B, BAM, suspended work, custom code, security, migration tooling, and coexistence.

FEYNMAN

BizTalk to Azure - Feynman Way

Start from what BizTalk was really doing: accept, normalize, route, remember, decide, deliver, and recover. Then derive the Azure design from those responsibilities instead of memorizing a replacement table.

core rule

Do not migrate product topology. Migrate required business behavior, contracts, reliability, and operational outcomes.

current direction

BizTalk Server 2020 is the final BizTalk Server release. Microsoft currently positions Azure Logic Apps Standard as the successor and provides a Migration Agent to assist discovery, planning, conversion, validation, and deployment.
